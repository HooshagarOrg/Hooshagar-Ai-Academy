## ۳) تصمیم بک‌آپ و آروان (§۷ GAP_AUDIT)

### سؤال: بهترین انتخاب آروان است؟

**آروان مقصد ذخیره است، نه موتور بک‌آپ دیتابیس.**

| لایه | نقش | توصیه |
|------|-----|--------|
| موتور بک‌آپ Postgres | `supabase db dump` / بک‌آپ پلتفرم Supabase | ضروری |
| محل نگه‌داری کپی شما | **آروان S3** (همین الان برای فایل اپ استفاده می‌شود) | **بله — بهترین انتخاب برای ایران/این پروژه** |
| UI بک‌آپ داخل اپ (گزینه C) | بعداً | الان اولویت نیست |

### تصمیم پیشنهادی قفل‌شده (توصیه سازنده)

**گزینه ترکیبی: A′ + B**

1. **A′:** ارتقای Supabase به **Pro** اگر هنوز Free است → بک‌آپ روزانه پلتفرم + جلوگیری از pause  
2. **B:** dump شبانه/روزانه رمزشده به **باکت جدا** روی آروان (مثلاً `hooshagar-backups`) با نگهداری ۳۰–۶۰ روز  
3. **C:** سیستم بک‌آپ داخل اپ — بعد از پایدار شدن پایلوت  
4. **D:** هیچ‌کدام — غیرقابل‌قبول  

> اگر هزینه Pro الان ممکن نیست: حداقل **B alone** + تست restore ماهانه؛ ولی ریسک pause Free را آگاهانه بپذیرید یا هفته‌ای یک ping بزنید.

## ۴) مرور گفتگوی School setup error

**هدف گفتگو:** خطای ساخت مدرسه جدید + پاک‌نشدن داده دمو → کشف شد بسیاری از UIها «تئاتری»اند.  
**خروجی:** `docs/GAP_AUDIT.md`  
**درس:** مشکل فقط بک‌آپ نبود؛ الگوی تکراری **UI/migration هست، مسیر end-to-end نیست**.

مواردی که در آن مسیر fix شده یا باید جدا پیگیری شود:
- ساخت مدرسه / کاربر با ایمیل ساختگی (بخشی عملی شده طبق audit §۶)
- school-settings هنوز mock (High)
- پاک دمو اگر فقط localStorage بوده، با «پاک کردن DB» یکی نیست

## ۵) مرور گفتگوی تست پایلوت

**هدف:** تأیید آمادگی میدان روی `www.hooshagar.ir` (~۳۰–۶۰ دقیقه) با نقش‌ها، OTP، AI، SMS، موبایل.  
**خروجی:** `docs/PILOT_TEST_CHECKLIST.md` (+ الگوهای کاوه‌نگار)  
**وضعیت:** چک‌لیست نوشته شده؛ اجرای مشترک هنوز انجام نشده (همه `[ ]`).

**نکته:** تست پایلوت را **بعد از** بستن حیاتی‌های Gap (حداقل: بک‌آپ تصمیم‌شده + مخفی‌کردن مالی/پیام جعلی + رفع AI access تصادفی) اجرا کنید تا نتیجه گمراه‌کننده نباشد. اگر عجله دارید: تست «دود سیگار» لاگین/OTP را زودتر هم می‌توان زد.
