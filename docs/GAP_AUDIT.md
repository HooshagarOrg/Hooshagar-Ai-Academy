# Gap Audit — هوشاگر (پایلوت مدرسه‌ای)

**تاریخ:** ۱۴۰۵/۰۵/۰۳ (۲۵ ژوئیه ۲۰۲۶)  
**محدوده:** production فعلی `https://www.hooshagar.ir` — پایلوت یک مدرسه  
**هدف:** شفاف‌سازی شکاف‌های «به‌نظر تمام / واقعاً نیمه‌کاره» قبل از تصمیم بک‌آپ  
**وضعیت این سند:** فقط گزارش — **هیچ تغییری در کد به‌خاطر این audit اعمال نشده**

---

## ۱) خلاصه اجرایی

پروژه برای مسیرهای **ورود (کد/OTP/PIN)، بخشی از داشبوردها، AI با سهمیه، اعلان، گزارش والدین** نسبتاً عملی است.  
اما چند لایهٔ حیاتی یا **اسکچ**اند، یا **UI تئاتری** (دادهٔ نمونه + ذخیرهٔ جعلی)، یا در مستندات **بیش‌ازحد کامل** اعلام شده‌اند.

| دسته | تعداد تقریبی | مثال |
|------|---------------|------|
| حیاتی (Critical) | ~۶ | بک‌آپ اپ، AI access تصادفی، مالی/پیام جعلی، GDPR حذف ناقص |
| بالا (High) | ~۲۰+ | تنظیمات مدرسه، صفحات ادمین AI، چند جریان معلم/والد/مشاور |
| متوسط | متعدد | observability، cron SMS، GDPR export ناقص |
| پذیرفته برای پایلوت | عمدی | stub معاونت‌ها، SMS مالی/برودکست خاموش |

**تصمیم فوری پیشنهادی:** قبل از گسترش کاربران واقعی مدرسه، روی **بک‌آپ/بازیابی** و **پنهان‌کردن یا برچسب‌زدن صفحات mock مالی/پیام** توافق کنید. بقیه را می‌توان زمان‌بندی کرد.

## ۲) تعاریف شدت

| شدت | معنی برای پایلوت |
|-----|-------------------|
| **Critical** | ریسک از دست رفتن داده، اعتماد مالی، یا کنترل دسترسی اشتباه — باید قبل از اعتماد عملیاتی تصمیم گرفته شود |
| **High** | کاربر فکر می‌کند ذخیره/تنظیم واقعی شده؛ یا امنیت/هزینه در معرض خطر است |
| **Medium** | ناقص ولی مسیر جایگزین دارد یا اثر محدود دارد |
| **Low** | کیفیت/سازگاری؛ مسدودکننده نیست |
| **Accepted-for-pilot** | آگاهانه در مستندات پایلوت پذیرفته شده |

## ۴) شکاف‌های بالا (High)

### ۴.۱ عملیات و زیرساخت

| موضوع | واقعیت | شواهد |
|--------|--------|--------|
| برندینگ / تنظیمات مدرسه | UI mock؛ `setTimeout` به‌جای ذخیره؛ RPCهای DB (`get/update_school_branding`) استفاده نمی‌شوند | `admin/school-settings/page.tsx`؛ `add_school_branding.sql`؛ `SchoolLogo` |
| آپلود لوگو در تنظیمات | به آروان وصل نیست (برخلاف `/api/upload` که واقعی است) | school-settings vs `lib/arvan-storage.ts` |
| Edge SMS هفتگی + cron | کد Edge هست؛ deploy/زمان‌بندی در repo تضمین نشده | `supabase/functions/*-weekly-sms`؛ وضعیت docs هنوز «منتظر» |
| صفحات `app/test-*` | در درخت اپ باقی‌اند (ریسک production) | گزارش‌های audit قبلی + وجود مسیرها |
| Login credentials در JSON پاسخ | هنوز `credentials: { email, password }` برمی‌گردد؛ Readiness ادعا کرده «رفع‌شده» | `login/route.ts`؛ drift در `DEPLOYMENT_READINESS.md` |
| Rate-limit fail-open | روی خطای DB اجازه می‌دهد | `lib/rate-limit-user.ts` (الگو) |

### ۴.۳ معلم / والد / مشاور

|------|---------------------------|
| معلم | behavior، content-creator، academic-foundation، weekly-report، parent-message، oral-questions |

## ۵) متوسط / پایین / پذیرفته برای پایلوت

### Medium
- GDPR **export** ناقص (زیرمجموعهٔ جداول)
- Observability: health هست؛ Sentry/Analytics عمدتاً خاموش یا فقط log
- `/api/ready` همیشه ready
- دو دامنهٔ ایمیل ساختگی (`users.hooshagar.ir` vs `{role}.hooshagar.ir`)
- والد بدون موبایل در bulk import → OTP کار نمی‌کند (login-code کار می‌کند)
- تست‌های GDPR placeholder

### Low
- Drift چک‌لیست migration (`backup_schedules` در چک‌ها هست، در migration نیست)
- Register عمومی هنوز ایمیل‌محور (مسیر مدرسه: ادمین/bulk)

### Accepted-for-pilot (عمدی و مستند)
- ~۳۵ صفحه معاونت/کارکنان با «پایلوت — به‌زودی»
- SMS مالی و broadcast غیرفعال (۵۰۳ / اجباری خاموش)
- SMS حضور خاموش
- مقیاس ۵۰k خارج از scope
- Middleware exclude `/api` با اتکا به `withAuth` per-route

## ۷) بک‌آپ — تصمیم قفل‌شده (Master Ops)

> **تصمیم:** مسیر **A′ + B** (۲۵ ژوئیه ۲۰۲۶). گزینه D مردود. گزینه C بعد از پایلوت.

| لایه | اقدام |
|------|--------|
| A′ | ارتقا به Supabase Pro در صورت Free + تأیید Daily backups — جلوگیری از pause |
| B | GitHub Action dump → باکت جدا آروان — [`docs/BACKUP_RUNBOOK.md`](BACKUP_RUNBOOK.md) |
| مقصد | آروان = انبار؛ موتور = `supabase db dump` / بک‌آپ پلتفرم |

### وضعیت اجرا
- Runbook و workflow بک‌آپ در Master Ops پیاده‌سازی می‌شوند.
- اسکچ `045` همچنان غیرعملیاتی است و جایگزین B نیست.

## ۸) اولویت پیشنهادی کار (پس از تصمیم بک‌آپ)

ترتیب پیشنهادی برای کاهش ریسک پایلوت — **نه تعهد زمان‌بندی**:

1. **تصمیم + اجرای بک‌آپ/بازیابی** (گزینه A حداقل، B ترجیحی)  
2. **پنهان/برچسب صفحات مالی و پیام** تا اتصال واقعی  
3. **رفع AI check-access تصادفی**  
4. **حذف/مسدود کردن `app/test-*` در production**  
5. **قطع برگشت password در پاسخ login**  
6. **وصل کردن school-settings به DB + آروان**  
7. **صفحات ادمین AI mock → واقعی یا مخفی**  
8. **جریان‌های معلم/والد mock با اولویت استفادهٔ واقعی مدرسه**  
9. **تکمیل GDPR و PIN hashing**  
10. **Observability حداقلی (خطا + آلرت)**

## ۹) اصلاح ادعاهای مستندات (بدون دست‌زدن به کد)

این فایل‌ها وضعیت را خوش‌بینانه‌تر از واقعیت نشان می‌دهند و باید بعداً هم‌تراز شوند:

| سند | مشکل |
|-----|------|
| `.cursorrules` Scratchpad (~100٪ پایلوت) | فازها «کامل»؛ صفحات mock زیاد نادیده گرفته شده |
| `docs/DEPLOYMENT_READINESS.md` | نقش‌ها «فعال»؛ ادعای رفع credential leak با کد هم‌خوان نیست |
